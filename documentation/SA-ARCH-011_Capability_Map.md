## How to read this

A **capability** is a named thing SmartArchive can do, not a module, not an endpoint, not a table. "Storage" is a capability; `storage_service.py` is one implementation of it today. Each capability lists: what it covers, its current maturity (cross-referenced to the Maturity Matrix in [SA-ROADMAP-001](SA-ROADMAP-001_Architecture_Roadmap.md)), the governing architecture document, and an **Owner** field left unassigned — this becomes real once a team structure exists to assign it to; leaving it visibly blank is more honest than inventing placeholder ownership.

## Governance Notes

- **Every feature belongs to exactly one capability.** If a proposed feature doesn't fit any row above, that's a signal either the capability list is incomplete (add a row, with a note on why) or the feature is actually two capabilities bundled together (split it before building).
- **Every capability belongs to one owner**, once a team exists to own it. Until then, the blank `Owner` column is itself useful signal — it shows at a glance which capabilities have nobody accountable for their architecture yet.
- **Cross-reference discipline:** future ADRs should say "this affects the Search capability" rather than "this affects `backend/app/services/search_service.py`" wherever possible — file paths change under refactoring, capability names shouldn't.
