What works (keep)

  • Product claim discipline: No invented certifications, encryption specs, or statistics — matches Page 1 “Protected with best practices” honesty.
  • User-control spine: Control + responsibility sections already end in human agency, same north star as Page 2’s “Your decision.”
  • Honesty tags: Demo / Concept labels are present where demos or future lifecycle story appear.
  • Token reuse: Petrol dark bands, gold decision tint, concept purple for lifecycle — Weave palette, no third design system.
  • Copy substance: Privacy / control / storage / transparency / lifecycle / responsibility titles and bodies are clear and founder-usable as locked wording for this direction pass.

What fails the Page 1–2 quality bar (must change in redesign)

  • Generic trust-page shape: Stacked centered text + icon blocks read as a SaaS security brochure, not the same editorial document world as approved Page 1 / Page 2.
  • Almost no photographic continuity: Hero is a small bordered UI card. The page never lands in the private-archive world Pages 1–2 established — so it fails brand continuity even though a full photo essay would also be wrong for this page’s job.
  • Hero “A” badge + coral eyebrow: Eyebrow uses text-accent (coral) for “Security & Trust.” Coral is CTA-only on Pages 1–2. The avatar “A” pill also uses coral tint — looks like a product avatar, not trust storytelling.
  • Shield-as-default iconography: Privacy opens with a shield icon. That pulls the page toward generic security wallpaper instead of document-life continuity.
  • Two dark bands stacked: Responsibility and CTA are both petrol/dark with little compositional difference — fatigue + weak close.
  • Lifecycle is thin: Four dashed dots are honest as Concept, but visually underweight next to Page 2’s Weave story language.
  • No section rhythm: Alternating recessed/light text slabs feel interchangeable. Nothing forces a different visual moment per job.
  • Not brand-first in the first viewport: Split headline + inset card does not match the full-bleed / dominant visual bar set by Page 1 hero photography.
Audit verdict

Page 3’s words are largely right. Its visual system is not yet in the same family as approved Page 1 and Page 2. The failure mode is “generic trust brochure,” not “missing a five-photo essay.” Redesign must raise continuity and rhythm without turning a principles page into another document-story page.

2. One coherent visual direction

Open question — answered (do not skip)

Should Page 3 use real photography at all?

Call: Yes — but only once. One dedicated hero photograph anchors Page 3 in the same private-archive world as Pages 1–2. Everything after the hero is type / SVG / gold decision language — no second or third photo.

  • Why not photography-heavy (Page 2 formula): Page 2’s job is continuous attention to a document (closer look → quiet help → prep → reminder). Page 3’s job is principles: ownership, isolation, source-trace, responsibility. Stacking desk photos on every claim becomes marketing theater and competes with Page 2’s narrative.
  • Why not zero photography: Current Page 3 already tried type+icon and reads as a SaaS security brochure. Page 1’s trust band is deliberately quiet and type-led as a section; a full /security page with no photographic anchor fails the brand-continuity test against the approved public site.
  • Why hero-only is enough: One private-archive still buys product continuity; structural claims (isolation, source link, lifecycle) stay honest as SVG/type — matching claim type to visual mode.

Product sentence (locked for this page)

Page 3 is the quiet afterword to understanding: the same documents, the same person, the same desk — protected because control stays with you. Trust is not a padlock catalogue. Trust is continuity of ownership, visibility, and decision.

Direction name

“Protected continuity.” One editorial trust page: one photographic arrival into the private archive, then calm principle sections in type/SVG — same Weave tokens and honesty system as Pages 1–2, deliberately fewer photos than Page 2. No feature grid. No certification theater.

Hard visual rules (stop a new loop)

  • No 2×2 / 2×3 shield or lock feature catalogue.
  • No mixing real photography and illustrative SVG as co-equal primary visuals inside one section.
  • At most one photographic primary on the whole page (hero). Do not default to a Page 2 multi-slot photo pass.
  • No inventing a second protagonist if photography is used. Same adult / desk / light as Page 1 hero + Page 2 bible.
  • No real government seals or legible real authority/institution names in any document imagery — fictional only (Example Administration / Amt für Beispiele / Example City).
  • Gold (--accent-2) = ownership, decisions, “what is protected that matters.” Coral (--accent) = CTA buttons only — never section eyebrows, never “private” labels, never trust badges.
  • Preserve Demo / Concept / Illustrative labeling exactly as established (same keys / same per-element logic).
  • Preserve non-specific security claim discipline — no fake ISO badges, encryption bit-depths, or uptime percentages. No padlock / shield-check / hacker / matrix clichés.
  • Each section = one job, one headline, one supporting sentence, one primary visual idea.
  • Do not duplicate Page 1’s quiet four-point trust row as the whole of Page 3 — expand the promise; don’t re-paste the homepage band.

3. Narrative — top to bottom

  1. Arrive in the private archive — same world as Pages 1–2; documents are personal, not a marketing vault.
  2. Ownership — what you upload stays yours; SmartArchive uses it to help you, not to sell you.
  3. Control — suggestions exist; nothing important proceeds without you.
  4. Separation — your archive is isolated; not a shared pile.
  5. Traceability — every explanation can return to the source document.
  6. Lifecycle visibility — upload → understand → store → keep or remove, always visible to you (Concept honesty).
  7. Responsibility — SmartArchive assists; you decide; you remain responsible.
  8. Close — security is foundation, then CTA.

Emotional arc: calm → ownership → agency → isolation clarity → checkability → continuity → adult responsibility → quiet confidence.

7. Color / token rules

  • Gold --accent-2: ownership signals, decision blocks, “what matters” marks, private-to-you emphasis. Not decorative chrome.
  • Coral --accent: Start for Free / primary actions only. Fix current hero eyebrow (text-accent) in implementation — planning calls it out now.
  • Petrol / teal: understanding, Weave edges, source-link cues, dark responsibility band.
  • Concept purple: lifecycle Concept visualization only — dashed honesty, not “premium security purple.”
  • Surfaces: page cream, recessed sage, card white — same Weave tokens. No new tokens.
  • No glow, no multi-layer neon shadows, no purple-on-white security theme.
